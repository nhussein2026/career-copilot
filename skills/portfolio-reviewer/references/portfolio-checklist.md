# Portfolio audit checklist

Walk every item. For each fail, name the exact offending element so the fix is actionable. A portfolio is linked from the resume and clicked for seconds — it must prove value fast and never show a broken link.

## 1. Value proposition (the first screen)
- [ ] States **who you are + what you build + for whom** within the first screen, no scrolling
- [ ] A real role/specialization, not just a name and "Welcome" or a generic tagline
- [ ] Front-loads the target-role keywords (recruiters and search both read this first)
- [ ] A clear primary call to action visible immediately (contact, view work, or download resume)

## 2. Projects / work (the core)
- [ ] 3–6 curated projects, strongest first — quality over a long dump
- [ ] Each project states: the problem, the candidate's role, the stack, and the outcome
- [ ] Each has **two working links**: a live demo and the source code
- [ ] Screenshots or short demos, not walls of text
- [ ] No tutorial/CRUD clones presented as flagship work (they undercut credibility)
- [ ] Featured projects match the target role and the resume's highlighted projects

## 3. Proof & credibility
- [ ] About section with a concrete, first-person story — not lorem-ipsum or a stub
- [ ] Real skills, honestly leveled; grouped and scannable
- [ ] Any metrics/claims are truthful and match the resume
- [ ] Optional but strong: writing/blog, talks, testimonials, or contribution links

## 4. Contact & conversion
- [ ] Obvious way to make contact (email or form) that actually works
- [ ] Links to GitHub, LinkedIn, and a downloadable/linked resume — all resolving
- [ ] Social/professional links open the right, current profiles

## 5. Discoverability & technical hygiene
- [ ] Descriptive page `<title>` and a meta description (not "React App" or "Vite + React")
- [ ] Content is real text in the HTML, not trapped in images or a JS-only render (search + quick loads must see it)
- [ ] Custom domain, or at least a clean, professional URL
- [ ] HTTPS; the site loads reasonably fast (no multi-MB hero image)

## 6. Responsive & accessible
- [ ] Works on mobile (recruiters open links on phones) — no horizontal scroll, tap targets usable
- [ ] Images have alt text; text has sufficient contrast; headings are real headings
- [ ] No broken layout, placeholder text, or "coming soon" sections left live

## 7. Consistency with resume / LinkedIn
- [ ] Name, current title, and dates match the resume and LinkedIn exactly
- [ ] The projects and skills emphasized point at the same target role across all three
- [ ] Technology names spelled correctly and consistently (JavaScript, Node.js, PostgreSQL, React)
